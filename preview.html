🌱 Beginner guide — read this and you are a professional

“Let's work this out in a step-by-step way to be sure we have the right answer.” That is the whole method of this repo: never believe a claim — run it.

Step 1 — Computers only understand numbers. Text like Hello must become numbers before any AI can read it. Those numbers are called tokens.
Step 2 — The simplest idea: one character = one token. H e l l o → [72,101,108,108,111]. Works for English, explodes for Korean/emoji (150,000+ characters and growing).
Step 3 — Better idea: UTF-8 bytes (only 256 possibilities). Every character on Earth becomes 1–4 bytes. Only 256 starting pieces — tiny dictionary, but very long sequences.
Step 4 — Best idea: BPE merges frequent pairs. Count the most common byte pair (e.g. e + space occurred 20×), mint a new token 256, replace everywhere, repeat. 20 merges ≈ 1.27× shorter. 50,000 merges ≈ GPT-2. 100,000 ≈ GPT-4.
Step 5 — One safety rail: never merge across word boundaries. A regex chops text into chunks first (dog | . | dog | !). That is why dog. never becomes one token — and why 4 spaces in Python broke GPT-2 but not GPT-4.
Step 6 — Special tokens glue documents together. <|endoftext|> separates documents; chat models add <|im_start|>/<|im_end|> per message. They are swapped in by exact match — which is also why pasting them can confuse a bot.
Step 7 — Now you are dangerous (in a good way). Costs, context limits, spelling failures, bad-at-math, non-English quality — all fall out of steps 1–6. The Quiz below checks each one.

🌐 View as a website (GitHub Pages — 2 minutes)

This page you are reading is the website. To publish it for your repo:

  1. Push this repo to GitHub (keep the docs/ folder as-is).
  2. Open Settings → Pages.
  3. Under Build and deployment → Source choose Deploy from a branch.
  4. Branch: main (or master), folder: /docs → Save.
  5. Wait ~1 minute, then open https://<you>.github.io/<repo>/preview.html.

Why /docs? GitHub Pages serves static files directly — no build step. docs/preview.html, docs/demo.gif, and docs/figures/ are all relative-linked, so they work both locally (open docs/preview.html) and on Pages. No action or custom domain required.
